# Initial Feasibility Study

## 1. Technical Feasibility

The system can be developed using the technologies, software, and resources available for a web-based project. The main functions we plan to develop are user registration and login, searching and filtering spaces, viewing space details and availability, making and managing bookings, notifications, and an admin dashboard. The system will also need a database to manage information such as users, spaces, availability, and reservations.

The project does not require special hardware because features such as IoT sensors and smart access using QR codes, NFC, or biometric authentication are outside the scope of the current version. We are also focusing on a web-based system rather than developing separate Android and iOS applications. This keeps the technical work within the planned scope and makes the project more manageable for the team.

## 2. Economic Feasibility

The expected costs and resources for the project are reasonable because the current version focuses on a web-based booking system. Features that may require additional resources, such as online payment processing, IoT sensors, smart access systems, and native mobile applications, are not included in the current scope.

The main resources needed will be the software and tools required to develop the system and the time and effort of the team members. A possible limitation is that adding some of the out-of-scope features in the future may require additional resources and costs.

## 3. Operational Feasibility

The system solves a real problem because existing workspace booking systems in the UAE are usually limited to certain institutions or are mainly made for professional users. Our system gives students, freelancers, remote workers, and other users one place to find and book a suitable space for studying or working.

They can search based on things like location, date, time, capacity, and available facilities. They can also make, change, or cancel their bookings. Space administrators can manage the spaces, availability, and reservations. We think users would use the system because it makes finding and booking a suitable space easier and more organized.

## 4. Schedule Feasibility

The project can be completed within the course duration because the work is already divided into different parts. We will start with User Management, then Space Search and Selection, Booking Management, Real-Time Availability and Notifications, and finally Administration.

Since we are using the Incremental Model, we can finish and test one part before moving to the next. This makes the project easier to manage during the semester. The main limitation could be if some tasks take longer than planned, so we will divide the tasks between the team members and keep track of the deadlines.

## 5. Overall Feasibility

Overall, we believe our project is feasible. The system focuses on the main features we planned, such as finding spaces, checking availability, making and managing bookings, and managing spaces. We also kept features like online payments, IoT, smart access, and mobile applications outside our current scope.

The main limitations are the course time and possible technical or schedule problems. By working on the system in increments and dividing the tasks between the team members, we believe we can complete the planned system within the course.
