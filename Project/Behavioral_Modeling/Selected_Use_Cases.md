# Exercise 1: Select Three Major Use Cases

| Use Case ID | Use Case Name | Primary Actor | Purpose | Reason for Selection |
|---|---|---|---|---|
| UC01 | Search for Spaces | User | To allow users to search for study rooms, meeting rooms, desks, and co-working spaces using criteria such as location, date, time, duration, capacity, and facilities. The system retrieves matching external space information through the supported DeskOS API operations and displays the results. | This is a core system function and demonstrates interactions between the User, SpaceSearch, Space, Location, Facility, and the external DeskOS API. It is suitable for modeling how search criteria are submitted, external results are processed, and matching spaces are displayed. |
| UC02 | Make Booking | User | To allow a user to select a suitable space and submit a booking request. The system checks the available information, processes the request through the DeskOS API booking operation  and records the booking details and status through callbacks. | Booking is a major system function that involves interactions among the User, Space, Availability, Booking, and BookingService classes. The sequence diagram can demonstrate request validation, availability checking, communication with the external system when supported, and the handling of the booking result. |
| UC03 | Manage Platform Booking Records | Administrator | To allow the administrator to review and manage booking records maintained by the platform. The administrator can inspect booking details and initiate an external cancellation only when the relevant DeskOS API operation  authorizes it. Externally controlled booking-status changes are reflected only from valid responses or callbacks. | This use case demonstrates administrative functionality and interactions among the PlatformAdmin, Booking, BookingService, and relevant external integration components. It also shows the distinction between managing platform booking records and directly controlling external providers' bookings or source availability. |
