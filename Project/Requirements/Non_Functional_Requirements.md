# 4.2. Non-Functional Requirements

The final consolidated non-functional requirements are listed in Table
4.2.

| **ID** | **Category**    | **Non-Functional Requirement**                                                                                                                                                                                                                                                |
|--------|-----------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| NFR-01 | Performance     | The system shall display space search results from cached DeskOS inventory within 3 seconds under normal operating conditions.                                                                                                                                                |
| NFR-02 | Security        | The system shall require users to log in before making or cancelling a booking.                                                                                                                                                                                               |
| NFR-03 | Usability       | The system shall display space details, including facilities and location, in a clear and understandable format.                                                                                                                                                              |
| NFR-04 | Reliability     | The system shall re-check availability from DeskOS after a booking is made or cancelled, so that the displayed availability reflects DeskOS. The system shall display the status DeskOS returns: confirmed, or pending_approval when the operator approves bookings manually. |
| NFR-05 | Portability     | The web-based system shall support access through Google Chrome, Microsoft Edge, and Mozilla Firefox.                                                                                                                                                                         |
| NFR-06 | Maintainability | The system shall let administrators change booking rules, such as the cancellation time limit, from the dashboard without editing the code.                                                                                                                                   |
| NFR-07 | Scalability     | The system shall support 500 simultaneous users and finish search or booking actions within 5 seconds by caching DeskOS inventory, because the default DeskOS limits are 6,000 reads and 600 writes per hour.                                                                 |
| NFR-08 | Responsiveness  | The system shall adjust its layout to fit desktop, tablet, and mobile screens without horizontal scrolling.                                                                                                                                                                   |
| NFR-09 | Robustness      | The system shall show an error message when users enter invalid data or try to book an unavailable room.                                                                                                                                                                      |
| NFR-10 | Accessibility   | The system shall allow users to search for rooms and manage their bookings using only a keyboard.                                                                                                                                                                             |
| NFR-11 | Availability    | The system shall be available at least 99% of the time during normal operating hours, excluding planned maintenance.                                                                                                                                                          |
| NFR-12 | Security        | The system shall lock a user account for 5 minutes after 5 consecutive unsuccessful login attempts.                                                                                                                                                                           |
| NFR-13 | Recoverability  | The system shall create a backup of user and booking data at least once every 24 hours so that the data can be restored in case of system failure.                                                                                                                            |
| NFR-14 | Privacy         | The system shall restrict access to users' personal information and booking history to the user and authorized administrators.                                                                                                                                                |
| NFR-15 | Data Integrity  | For DeskOS spaces, the system shall rely on DeskOS to reject overlapping bookings and show its error to the second user, so that two users cannot successfully book the same space for overlapping date and time periods.                                                     |
| NFR-16 | Reliability     | The system shall handle unavailable or unresponsive DeskOS API responses without causing the booking platform to crash, and shall renew the token on 401 and back off on 429.                                                                                                 |
| NFR-17 | Data Integrity  | The system shall validate space information and any availability information received from the DeskOS API before displaying it to users.                                                                                                                                      |
| NFR-18 | Performance     | The system shall process a successful response from the DeskOS live availability check (GET /availability) and display the corresponding availability within 5 seconds under normal operating conditions, excluding delays outside the system's control.                      |
| NFR-19 | Security        | The system shall verify the X-DeskOS-Signature header (HMAC-SHA256 of the raw request body with the shared secret, using a constant-time comparison) of each incoming DeskOS callback before accepting and processing its booking-status update.                              |
| NFR-20 | Reliability     | The system shall process duplicate deliveries of the same DeskOS callback so that a booking status is not updated more than once. DeskOS may resend a callback up to 5 times.                                                                                                 |
| NFR-21 | Reliability     | Every booking request shall carry an idempotency key, and a retry shall reuse the same key.                                                                                                                                                                                   |
| NFR-22 | Security        | The system shall store the DeskOS client ID and client secret only on the server and never send them to the browser                                                                                                                                                           |
