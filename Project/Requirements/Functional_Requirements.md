# 4.1. Functional Requirements

The final consolidated functional requirements are listed in Table 4.1,
with the scenario and use case each one traces to.

| **ID** | **Functional Requirement**                                                                                                                                                                                                                                                                                                                                                                                                    | **Traces To**      |
|--------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------|
| FR-01  | The system shall allow users to search for meeting rooms and day-pass desks by city, date, start time, duration, and number of seats. Virtual offices shall be shown as listing only, because they cannot be booked through DeskOS                                                                                                                                                                                            | S-01 / UC-01       |
| FR-02  | The system shall allow users to filter spaces based on facilities such as Wi-Fi, power outlets, whiteboards, and projectors, where the DeskOS inventory provides facility data. The platform shall apply this filter to the inventory data it retrieves.                                                                                                                                                                      | S-01 / UC-02       |
| FR-03  | The system shall allow users to view space details, facilities, and location before selecting a space.                                                                                                                                                                                                                                                                                                                        | S-01 / UC-03       |
| FR-04  | The system shall create bookings through POST /bookings, sending the booking type, campus, resource, the user as a guest (email required), a platform-generated external_ref, and an idempotency key. Meeting rooms shall be booked by start and end time, and day passes by date and seats. The system shall display the status DeskOS returns: confirmed, or pending_approval when the operator approves bookings manually. | S-01 / UC-04       |
| FR-05  | The system shall allow customers to cancel an existing booking up to one hour before its scheduled start time (platform rule). The system shall reject cancellation requests submitted less than one hour before the booking starts and display an explanatory message. For allowed requests, the system shall cancel the booking through POST /bookings/{external_ref}/cancel and show the resulting status.                 | S-02 / UC-05       |
| FR-06  | The system shall allow users to change an existing booking by creating a new booking for the new time, date, or room and then cancelling the original.                                                                                                                                                                                                                                                                        | S-03 / UC-06       |
| FR-07  | The system shall send users reminders before their scheduled booking time. only for bookings whose status is confirmed.                                                                                                                                                                                                                                                                                                       | S-05 / UC-07       |
| FR-08  | The system shall allow customers to request notifications for a specific space and time slot that is currently unavailable. The system shall detect when the slot becomes free by re-checking GET /availability at a fixed interval and then notify the customers who requested it.                                                                                                                                           | S-07 / UC-08       |
| FR-09  | The system shall retrieve all space listings from DeskOS. Administrators shall not be able to create, edit, or delete listings.                                                                                                                                                                                                                                                                                               | S-04 / UC-09       |
| FR-10  | The system shall allow users to create and update their profiles and view their booking history.                                                                                                                                                                                                                                                                                                                              | UC-10              |
| FR-11  | The system shall allow users to register for a new account using their name, email address, and password.                                                                                                                                                                                                                                                                                                                     | UC-11              |
| FR-12  | The system shall check availability before booking and show an error when DeskOS rejects the booking because the slot is taken.                                                                                                                                                                                                                                                                                               | S-01 / UC-04       |
| FR-13  | The system shall allow users to view their upcoming and previous bookings, including the space, date, time, and booking status.                                                                                                                                                                                                                                                                                               | UC-12              |
| FR-14  | The system shall allow administrators to manage reservations by viewing or cancelling bookings when necessary.                                                                                                                                                                                                                                                                                                                | S-04 / UC-13       |
| FR-15  | The system shall allow administrators to generate reports showing booking and space usage information, using platform records and GET /bookings totals (gross, commission, and net per currency).                                                                                                                                                                                                                             | S-04 / UC-14       |
| FR-16  | The system shall retrieve cities, opted-in operators, campuses (by city), and campus inventory from the DeskOS API.                                                                                                                                                                                                                                                                                                           | S-01, S-06 / UC-16 |
| FR-17  | The system shall process the space availability returned by GET /availability for each inventory item, including the reason code when unavailable (e.g., slot_taken, campus_closed), and display the relevant availability to users.                                                                                                                                                                                          | S-01, S-06 / UC-17 |
| FR-18  | The system shall allow the website administrator to view registered users, activate or deactivate accounts, and manage access to the platform.                                                                                                                                                                                                                                                                                | S-04 / UC-15       |
| FR-19  | The system shall receive booking-status callbacks from the DeskOS API for confirmed, rejected, and cancelled bookings. The backend shall verify and process each callback, update the corresponding booking record, and make the updated status available to the user. If a callback is missed, the system shall poll GET /bookings/{external_ref}.                                                                           | UC-18              |
