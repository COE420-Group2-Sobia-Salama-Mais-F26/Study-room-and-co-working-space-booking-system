# Exercise 3: Core Processes Matrix

| Process No. and Name | Input Data | Output Data | Rules |
|---|---|---|---|
| P1 – User Management | Registration information, login credentials, profile update information, booking history request | Registration confirmation, login confirmation, updated profile information, user information, booking history | The system shall validate registration information before creating an account. Users must provide valid credentials to log in. Only authenticated users can access their profiles and booking histories. Users can update only their own profile information. |
| P2 – Space Search and Selection | Space type, location, date, time, duration, capacity, facility requirements, space details request, availability information, external space information | Available spaces, search results, space details, facility information, location information, availability information | The system shall search for spaces according to the user's selected criteria. Results shall match the requested space type, location, capacity, facilities, date, and time. Users can filter spaces based on available facilities. External space information must be processed before being displayed. |
| P3 – Booking Management | Booking request, booking modification request, booking cancellation request, booking details, user information, selected space information, availability information | Booking confirmation, updated booking information, cancellation confirmation, booking status, upcoming bookings, previous bookings | A booking can only be created if the selected space is available. The system shall prevent overlapping bookings for the same space and time. Modifications must be checked against current availability. Cancellations must follow the booking cancellation policy and update the booking status. |
| P4 – Availability and Notification Management | Availability request, space status request, booking information, cancellation information, modification information, notification request, space and availability updates from the DeskOS API | Availability information, updated space availability, booking reminders, booking notifications, space-availability notifications | The system shall maintain current availability information. Availability shall be updated when bookings are created, modified, or cancelled. The system shall send booking reminders for upcoming bookings. Users who request an availability notification shall be notified when the requested space and time become available. Space and availability updates received from the DeskOS API shall be validated before being saved. |
| P5 – Administration | User management request, space management information, facility information, availability management information, reservation management request, room status request, report request, booking data, user data, space data | Updated user information, updated space information, updated availability information, reservation information, room status information, booking reports, usage reports, management confirmation | Only authorized administrators can manage users, spaces, availability, and reservations. Administrative changes must be validated before being saved. Administrators can view and manage user accounts, manage space information, manage reservations, monitor room status, and generate booking and usage reports. |
